01 / 具身智能

机器人能跳舞之后，下一步是把动作执行与任务生成接起来

00:00–02:51 · 07:23–14:54

讨论从机器人追踪动作的方式切入。发言人1把过去的路线概括为：先有一段参考动作，再训练机器人复现；他更看好全身实时遥操，让底层控制器能够追踪更多不同的动作。他以录音中提到的 Sonic 项目为例，解释大量运动轨迹如何支持更广的动作覆盖。大家随即追问：这些数据是视频还是关节轨迹、以什么格式存储、采集成本如何。

真正的分歧落在人形机器人的价值上。发言人3认为，当前技术还未充分发挥人形结构的优势；发言人1则把目光放得更远：人类活动数据丰富，生活环境也围绕人设计，通用人形有机会同时承接家务与运动陪伴。他提出一个工程判断：如果稳定的底层动作执行器与上层动作生成能够解耦，任务规划就更容易往上接。

这份乐观并未变成现场验证。发言人1预测 2027 年可能出现运动陪练产品，并用“洗碗、陪跑、打球”的多任务价值解释用户为什么可能付费。这是他的产品判断；发言人3对当前成熟度的保留意见，也应当一起留下。

02 / 软硬协同

FPGA 部署聊到最后：加速靠的是理解模型怎么算

15:47–24:36 · 74:56–76:54

一位参与 FPGA 项目的同学介绍了在可编程硬件上部署 Llama、适配注意力计算的经历。提问者最初把这件事理解成“设计一个类似 CPU 的处理器”，随后才逐渐对齐：工作需要读懂模型的计算流程，再围绕板上资源安排计算。

讨论落到了具体模块：位置编码、QK 矩阵乘法、Softmax、PV 矩阵乘法。算子本身的数学含义未必改变，但计算顺序、并行拆分和资源利用方式可以调整。所谓软硬协同，要求做硬件的人也理解软件与模型，才能知道该优化哪里。

端侧同学补充，CPU、GPU、NPU 的算子分配通常先交给厂商工具链，出现某段计算反而变慢时，再手动调整。现场也提到延迟、首 token 时间等指标。不过“十倍二十倍”的加速说法没有给出基线和测试条件，转写里的权重容量单位也不清楚，本期不把它们写成性能结论。

03 / 个人智能体

26:23–36:55

发言人2想要的个人智能体，能够综合随身摄像头、手表和其他传感器的信息，形成更完整的个人上下文。发言人3马上把愿景拆成工程问题：设备的通信方式、算力不同，每种数据该怎样处理？讨论由此从“接入更多设备”转向“如何整合异构信息”。

线上数据也有边界。与会者指出，不同应用之间的生态壁垒会限制智能体能知道什么；线下数据虽然值得探索，却又遇到采集设备、信息密度和回报周期的问题。讨论没有给出一个已经成熟的统一方案。

04 / 研究复盘

RSI 为什么在代码上好验证，到了科学绘图却难改好

37:07–42:42

聊到想转向更有技术壁垒的方向，发言人2拿自己做过的 RSI 实验举例。他讨论的是借助外部反馈，迭代改进工具或执行框架的做法，并不必然涉及重新训练模型。其体验是：在带有人类主观偏好的任务里，自动迭代效果很不稳定，经常需要人工介入。

代码任务相对容易构造反馈：测试是否通过、程序能否运行，通常能在环境中检查。科学绘图一类任务则很难仅靠人为编写的 rubric 给出可靠评价。问题不只在于改得够不够多，还在于模型有没有找对问题，以及提出的修改能否真正解决它。

发言人2特别提到，有时模型能指出问题，却不知道怎么改；有时连问题本身都没有提对。这使讨论从“多跑几轮就会变好”转到了评价信号的质量。这里记录的是一位实践者在特定任务中的经验，不足以推出所有人类偏好任务都无法通过自我改进受益。

05 / 自动科研

AutoResearch 能搜索组合，研究者仍要判断什么问题值得做

42:34–48:24 · 73:18–74:33

发言人2结合参与 AutoResearch 框架测试的经历，提出一个观察：模型能从已有方法中挑选、组合出有效方案，带来指标提升，但问题选择与方法的新意仍会卡住。即使给定一篇论文，要求基于其弱点继续研究，也可能遇到提问不合理或方案过于简单的问题。

他把这种差异描述为“组合搜索”与“启发式创新”的差别，并用会议层次表达自己对成果水平的判断。由于现场没有展示论文、评审意见或实验材料，这部分适合作为经验分享，不能当作自动科研能力的统一评级。

讨论随后转向 AI 辅助数学研究：即使工具擅长试错、检索和验证，研究者仍可提供方向，把通用能力推到具体问题的极致。到后半场，大家又把问题拉回自己：当 AI 能参与写论文、做项目，数量之外，更需要说明选题为什么重要、自己贡献了什么判断。

07 / 职业与落地

担心应用被下一代模型覆盖，大家把选方向聊成了选能力

57:08–65:55 · 82:12–84:24 · 90:17–92:08

一位同学担忧，自己做的绘图自动化、视觉重构等应用，会被下一轮模型能力覆盖，因此想转向推理加速或数据工程。这种担忧获得了回应，但讨论也提醒：越基础的岗位越看重可检验的基本功，选择一个听起来更坚实的方向，并不能省掉积累。

发言人1给出的另一条路径是，先在模型公司积累能力，再进入具体行业改造业务流程。他在现场把这类路径称为“IB”，强调两项本领：把任务指令与 Skill 写清楚，以及判断哪里该用模型、哪里该用规则。其价值最终要落在业务中能解决什么问题。

讨论里还有一个很实用的自测：看到一项工作时，能否主动指出几个可以改进的地方？这比追逐一个热门名词更接近独立判断。临近散场，有人问什么职业会一直存在，回答没有指向一个岗位，而是落在判断力，以及与人沟通、协调和推进事情的能力上。

08 / 前沿分歧

World Model 与 Agent：大家追问的是模型和工程各贡献了什么

77:57–85:11

临近尾声，话题转到 World Model、可交互世界与心智模型。发言人2最初把世界模型理解为具身智能的训练场：能否先生成一个可交互环境，让机器人在里面迭代？另一位发言人则提出保留意见，认为这种关联还需要更多证据来说明。

类似的追问也出现在 Agent 上。发言人1认为，部分 Agent 的长期独立价值需要接受更强基座模型的检验；发言人2把问题归纳为：效果究竟来自模型已有的智能，还是外部工程带来的提升？这并没有导向“Agent 没价值”的统一结论，而是要求把贡献拆开看。

现场提到的产品演示、岗位变化和心智模型论文都缺少可直接核对的材料。因此，本期将它们保留为后续调研线索。真正可以延续的问题是：生成一个可交互世界、训练一个可靠行动系统，以及做好具体任务的工具框架，分别需要怎样的验证？
